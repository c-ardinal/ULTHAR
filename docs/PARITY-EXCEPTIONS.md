# Parity exceptions

This is the authoritative list of `PE-<n>` ids: deliberate, documented points where
this Python runtime's behaviour differs from (or, for PE-19, simply has no
precedent in) an earlier PowerShell implementation of the same hook runtime. That
earlier implementation is not part of this repository and cannot be run or
compared against directly; each entry below is a *design decision record*, not a
live comparison result. `hooks/tests/fixtures/**/*.json` cite these ids on any
fixture whose expectation is intentionally one of these documented exceptions
(`"parity": false, "parity_exception": "PE-<n>"`), and `hooks/tests/parity.py` /
`hooks/tests/test_contract.py` cross-check that every id declared here is cited by
at least one fixture, and vice versa, so a documented exception can never silently
lose its test coverage and a fixture can never cite an undeclared id.

| id | Where | What changed / why |
|---|---|---|
| **PE-1** | `tool_discipline` delete-allowlist | Main-chain detection requires an empty `agent_id` **and** a transcript path not under a subagent-transcript path (both signals must agree). A tightening only: a subagent with an empty `agent_id` no longer gets allowlist access it should never have had. |
| **PE-2** | `skill_anchor` Write/Edit early-exit | Same two-signal main-chain check as PE-1. Effect: such a call simply no longer receives the anchor text; it never blocks. |
| **PE-3** | `commander` / `skill_anchor` "outside the project tree" check | Path containment is component-wise on normalised paths, not a raw string-prefix test (a prefix test would treat a sibling directory sharing a name prefix as "inside"). Tightens `commander`; for `skill_anchor` it only means fewer anchors are emitted, never a block. |
| **PE-4** | git command-line parsing, both `git_discipline` and `pr_state` | The two guards share one unified global-option prefix (recognising `-C`, `-c`, `--git-dir`, `--work-tree`, `--exec-path`, with quoted-argument support) instead of two independently-drifted regexes. Tightening only: an unrecognised global option could otherwise let a git subcommand slip past a check meant to catch it. |
| **PE-5** | `deploy` guard | Guards `.ps1` **and** `.py` (plus `config.json`, see PE-13) under the deployed hooks directory, recursively at any depth. The `.ps1` extension is guarded for anyone who keeps an optional rollback copy of an earlier PowerShell implementation around (none ships with this distribution); the `.py` coverage closes a hole a Python-based deploy would otherwise open by construction. |
| **PE-6** | `dev_process_hygiene`, `stop_dev_orphans` | Process discovery/kill/port-check go through a single cross-platform library (`psutil`) instead of two OS-specific code paths. Live process tables are not reproducible run-to-run, so this is unit-tested against a stubbed process list rather than compared live. |
| **PE-7** | `pr_state`, `git_discipline` | External command calls (`git`, `gh`) use split timeout budgets — a short one for local git plumbing, a longer one for the network-bound `gh` call — instead of being unbounded. Prevents a single shared budget from being wrong in both directions. |
| **PE-8** | all guards | A guard crash still results in the tool call being allowed (fail-open, unchanged), but now also appends a line to an error log. The exit code is unaffected; only the side effect is new. |
| **PE-9** | `brief_gate` length gate | Text length is measured in Unicode code points, not UTF-16 code units. Differs only for characters outside the Basic Multilingual Plane (e.g. some emoji) near the length threshold. |
| **PE-10** | message text, several guards | A small number of user-facing block messages were reworded because the old wording named a command, a path, or a file that no longer exists or is no longer accurate in this runtime (e.g. pointing at a retired installer script, or at a retired standalone data file that has since been folded into `config.json`). |
| **PE-11** | `install.py` | Deploys `config.json` plus the `lib/` and `guards/` directory trees (not a flat file list), refuses to deploy an invalid config, and checks dispatcher registration by looking for the Python entry point. These are observable differences in the install/verify commands' own output, not hook-time behaviour changes. |
| **PE-12** | `dev_process_hygiene`, `stop_dev_orphans` | The recognised process-name set adds `python3` (needed on platforms where the interpreter binary is named `python3` rather than `python`), matched by base name with a trailing `.exe` stripped for cross-platform comparison. |
| **PE-13** | `deploy_guard` | `config.json` under the deployed hooks directory is protected the same way a deployed guard module is — direct edits are blocked. The deployed config is a derived artifact exactly like the deployed code, and there is no reason it should be less protected. |
| **PE-14** | `git_discipline` blanket-staging messages | A message intentionally preserves a literal backtick pair around `` `git status` `` that a naive re-transcription might "fix" by removing — kept because the reference text this was ported from is documented (elsewhere) to have silently lost those backticks at its own parse time, and reproducing that loss here would be porting a known text-rendering defect forward on purpose. |
| **PE-15** | `commander` block message | Emits the correct `§` (section sign) character where an earlier, encoding-broken source rendered it as mojibake. The port fixes the encoding defect rather than reproducing it. |
| **PE-16** | `pr_state` block message | Same backtick-preservation reasoning as PE-14, for a different guard's message (`` `gh pr view <n> --json state` ``). |
| **PE-17** | `commander` / `skill_anchor` exempt-path matching | Exempt path patterns are matched after normalising path separators (backslash → forward slash), so a path spelled with either separator style is recognised consistently. Backslash-only patterns would match nothing at all on a platform whose paths never contain a backslash, which would silently defeat every exemption there — normalisation is required for this to work cross-platform at all, not a nicety. |
| **PE-18** | `git_discipline`, two new rule phases: `hook_bypass` and `force_push` | Blocks `--no-verify` / `--no-gpg-sign` on commit, and `--force` / `-f` / `--force-with-lease` on push (any destination branch), where no such rule existed before. `--no-signoff` and `-c commit.gpgsign=false` are deliberately out of scope (different risk class / different structural fix needed respectively — see `config.json`'s own notes on these two rules for the reasoning). |
| **PE-19** | `brief_gate`, compact header form | A new, optional compact header (`BRIEF: <file>.md \| <kind> \| no-ui`) that lets a dispatch satisfy several brief-gate checks by reference to one already-written approval file, instead of restating the same information as several separate inline markers. Purely additive — the long form keeps working unchanged. |
| **PE-20** | `skill_anchor` / `dispatch.events`, `PostCompact` registration removed | `config.json`'s `dispatch.events` no longer registers a `PostCompact` entry at all — the registration is deleted, not repaired. Removed because the Claude Code hooks documentation states that `PostCompact` stdout is never surfaced to the model (only `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`, and `PostModelSwitch` get their stdout injected as context) and that `PostCompact` carries no decision fields, so there is no output channel of any shape a registration on this event could use. The anchor text is already redelivered another way: `SessionStart` fires with `source=compact` after a compaction, and its stdout *is* injected, which makes a dedicated `PostCompact` registration redundant on top of being non-functional. Never a block either way; `skill_anchor` still exits 0 on every path, unchanged. An external `settings.json` hook registration for `PostCompact` can still exist and stay harmless — with no config-side route, dispatch resolves it to zero rules and returns allow with empty stdout. |
