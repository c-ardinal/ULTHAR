# Standard viewport test matrix（2026-09-04, owner directive）

マルチデバイス対応が要件の UI 作業では、受入前に**最低限**この行列の掃引検査を行う。
（発端: 640〜2020×1347 等の幅・高さの組合せでのみ再現するレイアウト欠陥が、
自動検査をすり抜けてオーナーの手動発見に回った。組合せ検査は自律的に行うこと
— オーナー明示指示。）

**正データはスキル直下の `config.json` の `viewport_matrix` セクション（配列・機械可読）。**
ハーネスは `config.json` を読み込み、`.viewport_matrix` を一段掘って参照する
（内側のキー形状は退役済み `references/viewport-matrix.json` とバイト互換に凍結済み — F-13）。
本ファイルは人間向けの説明で、軸の値は `config.json` が優先。

## 軸

- **幅 (px)**: 360, 390, 420, 555, 640, 768, 844, 1000, 1280, 1366, 1440, 1920, 2020, 2400, 2560
- **高さ (px)**: 390, 450, 700, 800, 844, 1080, 1347, 1440
- 組合せは全直積のうちアスペクト比 0.25〜4.0 の現実的な窓のみ（それ以外は skip 可、skip は列挙）
- プロジェクトのブレークポイント境界（±1px）を必ず追加（例: 1023.98/1024）

## 各組合せで検査する不変条件（プロジェクトの該当分すべて）

1. 意図しないページスクロールなし（設計がゼロスクロールなら scrollHeight ≦ viewport ±1px）
2. 要素のクロップ/はみ出し 0px（設計上の覗き・意図的例外は明記の上で除外）
3. 要素同士の重なり 0px（レイヤ設計上の重なりを除く）
4. 折りたたみ/展開などの応答状態が条件と整合（例: 収まらないなら必ずアイコン化）
5. 不当縮小なし（余裕がある軸を使わずにコンテンツを縮めない）
6. 死に空白なし（主要領域間の未使用ギャップが規定値以下）
7. タッチターゲット ≥44px（操作要素）

## 運用

- 実装はプロジェクト毎のハーネス（Playwright 等）で行い、pass/fail 行列と違反組合せの列挙を出力する
- フルスイープは受入時必須。ラウンド中の高速確認は代表 6〜8 点（縦 SP・横 SP・タブレット・ラップトップ・FHD・WQHD＋直近変更に近い境界）で可
- エンジン: chromium 必須、webkit はフルスイープ時または違反クラスのスポット確認
- ブリーフでは本ファイルを `viewport-matrix` として参照する（brief-gate-guard が responsive 系ブリーフで参照を要求）
